# Elkeid 企业级扩展 —— 整体方案与排期计划

> 范围：基于社区版 `bytedance/Elkeid`（main 分支）补齐企业级能力。
> **明确排除 Windows**（单列排期，本次不排）。本计划覆盖四大能力域：
> ① 白名单放行 ② 文件变动监控（FIM） ③ 内核安全 ④ 企业版功能对齐（Linux 侧）。
>
> 估算口径：`人日` = 1 名工程师 1 个工作日（8h）。默认按 **3 人核心团队**（内核 C / 插件 Rust·Go / 后端·前端）并行，可等比缩放。
> 许可约束：`driver` 为 **GPLv2**（改内核必须开源）；`agent/rasp/server` Apache-2.0；`console`、`HUB` 为 Elkeid License（商用前复核）。

---

## 1. 目标与验收总纲

| 能力域 | 目标 | 最终验收（DoD） |
|---|---|---|
| 白名单放行 | 控制台可配置进程/参数/网络白名单并实时下发到终端，命中即放行/降噪 | 控制台增删白名单 → Agent 内核生效（`/dev/hids_driver_allowlist` 可查）→ 命中事件不再告警 |
| 文件监控 | 关键路径文件创建/修改/删除/移动/改名可监控，支持完整性基线比对 | 指定目录变更在 Console 可见并告警，误报率可控，性能衰减 < 5% |
| 内核安全 | 模块加载/提权/端口扫描/文件删除等全量审计并告警，驱动可自保 | 白名单外 .ko 加载、可疑提权、端口扫描均能告警；root 无法轻易卸载/篡改驱动 |
| 企业版对齐 | 补齐扫描、基线、漏洞、资产、序列检测、聚合追溯等检测类能力 | 与官方功能表逐项对齐，检测类能力社区侧可自建；阻断/主动防御走决策门 |

## 2. 总体改造地图（WBS）

```
Elkeid 扩展
├─ P1 白名单放行
│   A1 静态白名单配置化
│   A2 driver 插件动态白名单（任务接收 + 内核下发）
│   A3 Manager 白名单管理 API
│   A4 Console 白名单页面
│   A5 HUB 告警白名单（降噪）
│   A6 联调与容量/TTL 测试
├─ P2 文件监控
│   B1 内核态写监控（W/R notifier + 608/609 钩子）
│   B2 fanotify FIM 插件（复用 FileMonitor）
│   B3 完整性基线比对（sha256 快照 diff）
│   B4 数据落点 + HUB 规则 + Console 展示
│   B5 性能与事件风暴限流测试
├─ P3 内核安全
│   C1 模块加载审计闭环（603 → 规则告警）
│   C2 打开 OFF 钩子（unlink/rmdir/file_write/kill 等）
│   C3 端口扫描检测（612 + psad_switch）
│   C4 驱动自保护（防卸载/设备权限）
│   C5 系统加固基线（baseline 扩充）
│   C6 eBPF/新一代威胁检测（进阶，另排）
└─ P4 企业版检测能力对齐
    D1 漏洞采集与 CVE 匹配
    D2 资产采集增强
    D3 病毒扫描接线（yara/clamav）
    D4 基线规则扩充
    D5 行为序列检测（HUB 状态机）
    D6 多告警聚合 + 告警追溯
    D7 主动防御/威胁响应/文件隔离（决策门）
```

## 3. 分阶段实施计划

### Phase 0 —— 准备（前置，1 周）

| 任务 | 内容 | 产出 |
|---|---|---|
| P0-1 编译发布流水线 | driver 插件(Rust musl) / collector·agent(Go) / scanner(Rust) / LKM(C) 四套编译 + 版本号 + Nginx 分发 | 一键构建 + 组件上传 |
| P0-2 测试环境 | 2~3 台覆盖内核 3.10 / 4.14 / 5.10+（CentOS/Ubuntu/Debian）的测试机 + LTP/KASAN 回归基座 | 可复现基线 |
| P0-3 数据字典冻结 | 汇总 schema.rs 各 data_type 字段 + collector/scanner 事件，形成内部字段字典 | 字段字典文档 |

> 说明：无 Phase 0，后续 P1–P4 无法稳定交付，排期上先行 1 周。

---

### Phase 1 —— 白名单放行（快速见效，低风险）

**目标**：控制台 → Manager → AC → driver 插件 → 内核白名单，全链路打通。

| ID | 任务 | 角色 | 人日 | 依赖 | 交付/验收 |
|---|---|---|---|---|---|
| A1 | `config.rs` 静态白名单 `EXE_WHITELIST/ARGV_WHITELIST/IPV4_FILTER/DNS_SUFFIX_WHITELIST` 配置化 | 插件 | 0.5 | P0-1 | 编译期放行可信程序生效 |
| A2 | driver 插件 `task_receive` 实现动态白名单：自定义 data_type（9002）+ JSON 协议 + 调 `kmod.add_filtered_exe/argv` | 插件 | 2.5 | A1 | 收到任务即写 `/dev/hids_driver_allowlist` |
| A3 | Manager 白名单管理 API：CRUD + 主机/分组绑定 + 下发任务 | 后端 | 3.5 | A2 | API 可下发、可回滚 |
| A4 | Console 白名单页面：进程/参数/IP/DNS 白名单编辑与下发 | 前端 | 4 | A3 | 页面操作 → 终端生效可查 |
| A5 | HUB 告警白名单规则（采集不丢、告警降噪） | 规则 | 2.5 | A2 | 命中规则 discard/降级 |
| A6 | 联调测试：64 元素容量、exe/argv TTL、容器/POD 命名空间、并发下发 | 测试 | 2.5 | A3,A4 | 容量/TTL/并发符合预期 |

**阶段产出**：进程/参数/网络白名单全链路可用。**约 15.5 人日**。

### Phase 2 —— 文件监控

**目标**：敏感目录变更可监控、可告警。

| ID | 任务 | 角色 | 人日 | 依赖 | 交付/验收 |
|---|---|---|---|---|---|
| B1 | 内核态写监控：driver 插件 `control()` 下发 `W/R` notifier + 打开 608/609 钩子 + transformer 补 608/609 映射 | 内核 | 4 | P0-2 | `/etc`、`/usr/bin` 写入可上报 |
| B2 | fanotify FIM 插件：复用 `fmonitor.rs` 的 `FileMonitor`，输出 create/modify/delete/move + hash | 插件 | 5 | P0-2 | 指定目录递归监控 |
| B3 | 完整性基线比对：sha256 快照 + 增量 diff（扩展 `integrity.go` 思路） | 插件 | 3.5 | B2 | 基线漂移告警 |
| B4 | 数据落点 + HUB 规则 + Console 文件监控页 | 后端·前端 | 3.5 | B1,B2 | 变更事件可查可告警 |
| B5 | 性能与限流：fanotify 大目录、事件风暴限流、性能衰减 < 5% | 测试 | 2.5 | B1,B2 | 压测达标 |

**阶段产出**：FIM 能力。**约 18.5 人日**。

| 周次 | 甲（内核C） | 乙（插件） | 丙（后端·前端·规则） | 里程碑 |

**关键里程碑**

**决策门（Gate）**
- **G1（W7 后）**：是否自研 `D7 主动防御/阻断`（20 人日，高风险）——驱动从“只读采集”改“可拦截”，需评估 GPLv2 合规与稳定性，否则转企业版采购。
- **G2（W8 后）**：是否投入 `C6 eBPF/新一代威胁检测`（12 人日）——取决于对抗需求优先级。

## 6. 风险与依赖

| 风险 | 影响 | 应对 |
|---|---|---|
| 内核版本碎片化（2.6.32~6.x） | B1/C2 钩子回归成本高 | P0 覆盖 3.10/4.14/5.10+ 三档；LTP 回归 |
| driver 改拦截/自保护（GPLv2） | 合规与稳定性风险 | D7 走决策门，默认转采购 |
| fanotify 事件风暴 | 性能/丢事件 | B5 限流 + 白名单路径过滤 |
| 白名单内核容量/TTL 限制（64 元素、10min/60s） | 动态白名单被回收 | 静态白名单 + 心跳续期设计 |
| 后端改造涉及 Manager/AC/Console/HUB 多模块 | 排期依赖串行 | 提前冻结数据字典（P0-3） |
| 规则/算法侧（序列检测、聚合追溯） | 工作量大且需攻防经验 | D5/D6 单独排期，先做框架后迭代 |

## 7. 建议启动顺序（排期执行口径）

1. **W1**：Phase 0 全量启动（环境/流水线/数据字典）。
2. **W2–W3**：白名单放行（A）与内核写监控（B1）并行推进，先交付 M1。
3. **W3–W5**：FIM（B）并行 C2–C4 内核安全，交付 M2。
4. **W5–W7**：内核安全收尾（C1/C3/C5）+ 检测能力启动（D1/D2/D4），交付 M3。
5. **W8–W12**：检测能力对齐（D3/D5/D6），G1/G2 决策，整体验收 M4/M5。

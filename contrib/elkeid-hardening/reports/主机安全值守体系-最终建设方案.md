## 0. 结论摘要（一页纸）

**选型：路线四** —— Tetragon（eBPF 策略执行）+ LKRG（内核完整性）+ 自研 Go/Rust 值守主控 + ClickHouse/ES/Grafana 管控面。

四项硬需求到实现的一一映射：

| 需求 | 执行组件 | 关键机制 | 语义 |
|---|---|---|---|
| ① 高危/核心命令内核态直接拦截 | Tetragon（BPF LSM） | `bprm_check_security` | **deny（-EPERM）**，进程从未存在 |
| ② 安全值守程序保活与自保护 | 自研 Go/Rust Watchdog | systemd 托管 + eBPF 防 kill -9 + 熔断降级 | 秒级拉起 |
| ③ 内核完整性与 Rootkit 防护 | LKRG（内核模块） | 内核文本段 + `cred` 结构体校验 | 检测 + 阻断 |
| ④ 文件变动监控与防篡改 | Tetragon + Watchdog fanotify 协程 | vfs 拦截 + 哈希基线审计 | deny + 审计 |

三条总原则：

1. **告警激进、阻断克制**：所有阻断默认 Observe，经三态灰度才 Enforce。
2. **命令拦截是入口，行为拦截是兜底**：对 `/dev/sd*` 的写、对 `/etc/passwd` 的改、`finit_module` 才是绕不过去的防线。
3. **管控面可断、主机不可失防**：管控面宕机或断网时，Agent 必须基于本地缓存规则独立执行拦截。

## 1. 需求与边界

### 1.1 四项硬需求（原话提炼）

1. 高危与核心命令**内核态直接拦截**（不是事后审计）。
2. 安全值守程序：进程异常退出自动拉起、防强杀（kill -9）、防卸载、资源过载熔断。
3. 内核完整性与 Rootkit 防护。
4. 核心目录与文件变动**实时**监控及防篡改。

### 1.2 环境硬约束（决定技术选型的前提）

| 约束 | 影响 | 已定的应对 |
|---|---|---|
| 物理隔离内网，无外部 SaaS | 不可用云厂商公有云方案 | 全离线自建，物料物理摆渡导入 |
| Ubuntu 26.04.1，内核统一 | 消除多档内核碎片 | eBPF CO-RE 一次编译多机运行 |
| 内核默认导出完整 BTF | CO-RE 前提满足 | `/sys/kernel/btf/vmlinux` 实测确认 |
| uutils coreutils + sudo-rs 默认 | 命令规则会静默失效 | 规则只匹配 path+argv，**禁 comm** |
| 内核移除 SHA-1 模块签名 | 旧签名模块拒载 | 全部 SHA-256 + MOK 预置公钥 |
| Secure Boot / Kernel Lockdown | out-of-tree 模块受限 | LKRG 必须签名 + MOK 信任 |

### 1.3 明确不做

- 不做全流量 NDR、不做病毒库特征匹配（交给现有 AV/HIDS）。
- 不做漏洞扫描（消费漏扫平台结果做资产关联）。
- 不做全量日志长期存储（只存安全事件 + 关键审计，180 天）。

## 3. 总体架构（三层）

```
┌───────────────────── 管控面（内网，双活-主备）─────────────────────┐
│  策略中心 · 事件检索(ClickHouse/ES+Grafana) · 告警路由 · 工单/报表  │
└──────────────▲─────────────────────────────────────▲──────────────┘
      策略下发 mTLS│（增量+签名，本地持久化兜底）      │事件上报(WAL→批量→zstd)
┌──────────────┴─────────────────────────────────────┴──────────────┐
│                    主机侧（每节点，systemd 托管）                  │
│                                                                   │
│   内核态                        用户态                            │
│  ┌────────────┐   ┌──────────────────────────────────────────┐   │
│  │ Tetragon   │──▶│ 事件总线(ringbuf) → 策略引擎 → 决策 → 执行 │   │
│  │ (BPF LSM   │   │    Go/Rust 值守主控                       │   │
│  │  /kprobe)  │   │  ① 保活/自保护 ② 熔断/降级 ③ fanotify FIM │   │
│  ├────────────┤   │  ④ 本地规则缓存 ⑤ 上报/断网缓存            │   │
│  │ LKRG(模块) │   └──────────────────────────────────────────┘   │
│  └────────────┘                                                  │
└──────────────────────────────────────────────────────────────────┘
```

三条数据流：**热路径**（内核→ringbuf→决策→执行，不落盘不发网络）；**冷路径**（事件→WAL→批量→上报）；**控制路径**（策略版本化下发）。

## 4. 四大能力实现

### 4.1 核心命令拦截（deny 语义）

- **钩子**：LSM `bprm_check_security`，命中返回 `-EPERM`，进程从未被创建。
- **降级**：内核/组件版本不支持 LSM deny 时，退化为 kill(SIGKILL) 语义并**在规则上显式标注**，不做「假装同步阻断」。
- **字段规范（硬规定）**：一律匹配 execve 的**解析后路径（path）+ 命令行参数（argv）**，严禁匹配 `comm` —— uutils 的 multi-call 打包会令 `comm`/`argv[0]` 呈多路复用，导致规则静默失效。
- **热路径原则**：LSM 回调里只做 map 查表（O(1)），正则/语义解析全部前置到用户态；内核态程序无循环、无睡眠。
- **反弹 Shell / 异常外连**：Tetragon 挂钩 socket/connect 系统调用，告警 + 阻断联动。
- **重点命令清单**见附录 A。

### 4.2 安全值守程序（Watchdog）

| 职责 | 实现 |
|---|---|
| 保活 | Go/Rust 单二进制，systemd `Restart=always`；内置心跳检测，异常秒级拉起 |
| 防 kill -9 | Tetragon 策略拦截非白名单 `kill` 信号；防模块卸载同理 |
| 资源过载熔断 | 监控自身 CPU/内存/事件队列，超阈值触发降级 |
| 能力降级 Degraded Mode | 先保「命令拦截 + 防强杀」→ 降非核心文件哈希周期 → 必要时关高开销探针，宿主机可用性优先 |
| 自保护 | 自身文件/进程受 eBPF 保护；卸载需口令 + 工单 |

### 4.3 内核安全（LKRG）

- LKRG 作为唯一 out-of-tree 内核模块，**风险评级：中低**，职责是内核文本段与 `cred` 结构体完整性校验 + 非法提权阻断。
- **必须专项压测**：上线前在目标内核版本测机做高并发系统调用、模块加载/卸载压测。
- **卸载预案**：值守程序应急脚本执行安全卸载（`rmmod p_lkrg`），或切换至「仅启用 Tetragon」的降级模式。
- 硬化基线（sysctl/启动参数）随包下发，纳入每日完整性比对。

### 4.4 文件变动监控（FIM）

- **实时拦截**：Tetragon 拦截 `/etc`、`/boot`、`/usr/bin` 等关键路径的高危写/删/改权。
- **哈希审计**：值守主控内置 fanotify 协程，记录变更并计算 SHA-256 基线。
- **周期校验**：首次全量哈希 + 每日增量 + 每周全量，`ssdeep` 相似度区分「改配置」与「换文件」。
- **溯源**：事件携带完整进程/父进程/路径上下文，支撑血缘分析。

## 5. 策略引擎与误杀控制

### 5.1 规则模型

```yaml
apiVersion: watchdog/v1
kind: Rule
metadata: { id: R-EXEC-0012, name: 禁止删除根目录或系统关键目录, severity: critical }
spec:
  match:
    event: process_exec
    all:
      - exe_in: [/bin/rm, /usr/bin/rm]          # path，非 comm
      - argv_regex: '(^|\s)-[a-zA-Z]*[rf][a-zA-Z]*\s+(/|/\*|/etc|/usr|/var|/boot)(\s|$)'
  action: { type: deny }                          # 旧组件自动降级为 kill 并标注
  exception: { users: [deploy], hosts: ["tag:batch-job"] }
  rollout: { mode: enforce, percent: 100 }
```

### 5.2 三态灰度（Observe → Audit → Enforce）

| 阶段 | 行为 | 观察期 |
|---|---|---|
| Observe（观测） | 仅统计命中频次，不影响进程 | 建立基线 |
| Audit（审计告警） | 记录完整事件并上报告警，不拦截 | ≥72h，收敛白名单 |
| Enforce（强制拦截） | 批次放量（1%→10%→100% 节点），每步观察窗口期无误杀再推进 | 逐步 |

### 5.3 Kill Switch（一键熔断）

管控面 + Agent 本地**双通道**，秒级触发；异常时一键回退全部策略至 Audit 或放行，无需重新打包或重启主机。

### 5.4 白名单 TTL 与版本回滚

- 白名单强制 TTL（如 15d/30d/7d），到期自动失效并重新纳入审计，杜绝「永久白名单」。
- 策略包版本号 + 校验和，支持一键回滚至任一稳定版本。

## 6. 事件模型与数据管道

### 6.1 Schema（关键字段）

```json
{
  "event_id": "...", "ts": "2026-11-20T23:12:00+08:00",
  "host": { "id": "i-xxx", "kernel": "6.x", "tags": ["prod"] },
  "category": "process_exec",
  "subject": { "pid": 12873, "ppid": 12800, "uid": 0, "exe": "/usr/bin/rm",
               "cmdline": ["rm", "-rf", "/tmp/cache"], "cgroup": "..." },
  "object": { "path": "/usr/bin/rm", "hash": "sha256:..." },
  "action": { "decision": "deny", "rule_id": "R-EXEC-0012", "latency_us": 840 },
  "risk": { "score": 92, "tags": ["destructive", "root"] }
}
```

### 6.2 上报与存储

- 本地 WAL 先落盘 → 1000 条/5s 批量 → zstd 压缩 → mTLS → 边缘聚合。
- 断网缓存 ≥24h，恢复后按时间序补传。
- 存储：热 7 天（ClickHouse/ES）/ 温 90 天 / 冷 180 天（对象存储，满足等保 ≥6 个月）。

### 6.3 脱敏与去重（新增，防合规与成本翻车）

- **命令行脱敏**：命中 `password=`、`--token`、`Authorization:` 等模式，入库前打码。
- **事件去重聚合**：高频文件事件按「主机 + 路径 + 5 分钟窗口」聚合成摘要，只留首末条 + 计数；**阻断类事件永不聚合**。

## 7. 管控面（高可用与断连韧性）

- **组件**：策略中心 + 事件接收网关 + 告警路由 + ClickHouse/ES 存储 + Grafana 看板。
- **防单点**：关键服务双活-主备部署，避免单点故障导致无法下发规则或丢失告警。
- **断连韧性（核心约定）**：Agent 侧策略包与白名单持久落盘到受保护本地目录（`/var/lib/sec-guard/policies`），管控面不可达或宕机时，Agent 仍基于本地缓存策略独立执行命令拦截、文件防护与自保护；网络恢复后补传压缩事件。
- **灰度下发**：策略版本化 + 增量下发 + 生效回执，30 秒内可全量回滚。

---

## 8. 内核模块与密钥运维

- **LKRG 生命周期**：每次内核升级需在联网构建机拉取对应内核头文件，重编译 `p_lkrg.ko` → SHA-256 签名 → 更新 MOK 信任 → 摆渡入内网验证。
- **内核冻结窗口**：HWE 内核约每 6 个月发版，建立「季度-半年批构建摆渡」机制，避免零散升级。
- **MOK 密钥管理**：私钥离线保管、分级授权；签名与密钥管理规范纳入运维手册，作为交接必备项。

## 9. 安全值守闭环（SOP / SLA）

### 9.1 分级与时效

| 级别 | 首次响应 | 处置闭环 |
|---|---|---|
| P0 | 5 min | 30 min |
| P1 | 15 min | 2 h |
| P2 | 1 h | 24 h |
| P3 | 次日 | 1 周 |

### 9.2 处置 SOP

高危命令拦截 / 提权 / 篡改事件 → 事件入存储并推送飞书-企微-工单 → 值班人员核查进程血缘（path-argv-父进程）+ 主机基线 → 确认合法变更或入侵 → 按预案遏制/取证/恢复 → 复盘沉淀规则。

### 9.3 误杀止血

发现误杀 → 立即启用策略/全局 Kill Switch 回退放行或加带 TTL 的临时白名单 → 收敛规则并更新版本 → 复盘根因。

## 10. 验收标准

### 10.1 性能与稳定性（可量化判据）

| 指标 | 目标 |
|---|---|
| 空闲/峰值 CPU | <1% / <5% |
| 内存 RSS | <150MB |
| fork/exec 吞吐损耗 | <3% |
| 拦截时延 | deny：P99<5ms（进程无存活）；kill：存活 <10ms |
| 误报率 | 首轮过渡 **<1%** → 灰度收敛后稳态 **<0.1%**（高危阻断类规则） |
| 内核稳定性 | 100 节点压测 + **≥7 天**灰度 + 覆盖**至少一次内核升级**，零非预期 panic |
| 日志留存 | 180 天，命令行已脱敏 |

> 误报率阈值与 panic 观察期两项，相对 v2 定稿做了收紧口径：全新规则集首轮达不到 0.1%，先设过渡值；72h 对内核级组件偏短，改为 7 天起步。

### 10.2 功能验收

`rm -rf /` 命中率 100%；关键目录写入/改权/删除事前阻断；安全进程 kill -9 被拒；未签名模块加载被拒。

### 10.3 灰度验收

三态灰度走完整流程；Kill Switch 一键回退验证通过；断网 ≥24h 后 Agent 独立拦截正常。
